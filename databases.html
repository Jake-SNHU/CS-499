Category Three Narrative

The artifact I selected for the databases category is a Python application developed during CS 340 that uses MongoDB to manage and visualize data from the Austin Animal Center. The project consists of two primary components: a reusable CRUD Python module that performs database operations and an interactive Dash dashboard that allows users to search, filter, and visualize animal records. The original artifact was created during my Database Systems course and demonstrated the basic implementation of create, read, update, and delete operations using MongoDB. While the original project successfully met the course requirements, I recognized that it could be significantly improved by adding stronger database functionality, better error handling, enhanced querying capabilities, and a more interactive user interface. I selected this artifact because it demonstrates several important software development skills related to database design, data management, and user interaction. Database-driven applications are common in professional software development, and this project allowed me to demonstrate my ability to connect a backend database with an interactive front-end interface while following good software engineering practices. One of the most significant improvements was enhancing the CRUD module to support more advanced database operations. In the original project, the read() method simply accepted a query and returned every matching document. During this enhancement, I redesigned the method to support projections, sorting, and pagination through optional parameters. def read( self, query=None, projection=None, sort_field=None, ascending=True, page=1, page_size=100 ): Adding these parameters makes the module much more reusable because other applications can retrieve only the fields they need, sort the results by different attributes, and limit the number of returned records for improved performance. I also improved database reliability by validating the MongoDB connection during initialization. Instead of assuming that the connection would succeed, the enhanced constructor verifies the connection using: self.client.server_info() If the database cannot be reached, the application immediately reports the error rather than failing later during a query. This provides better fault detection and improves overall reliability. Another important enhancement involved replacing simple print statements with Python's logging framework. Throughout the CRUD module, successful operations and exceptions are now logged using statements such as: logging.info("Animal inserted successfully.") logging.error(f"Update failed: {e}") Using structured logging is a professional software engineering practice because it makes troubleshooting significantly easier and provides detailed information about application behavior without cluttering the console. To improve data integrity, I also added validation before inserting new records into MongoDB. The create() method now verifies that required fields such as the animal type, breed, name, and age exist before allowing the document to be inserted. required = [ "animal_type", "breed", "name", "age_upon_outcome_in_weeks" ] This prevents incomplete records from entering the database and demonstrates defensive programming techniques. Additional helper methods were added to make the CRUD module more reusable. These include methods such as search_by_breed(), search_rescue(), find_by_id(), and count(). Rather than repeatedly writing MongoDB queries throughout the dashboard, these methods encapsulate database functionality into reusable operations, improving maintainability and reducing duplicate code. The dashboard itself also received several significant improvements. The original dashboard only allowed users to filter animals by rescue category using radio buttons. I expanded the interface by adding a breed search box, a dynamic sorting dropdown, and a live animal counter. The breed search uses MongoDB regular expressions to perform case-insensitive searches: query["breed"] = { "$regex": search_value, "$options": "i" } This provides a much more flexible search experience than exact string matching. Sorting was also improved through a dropdown menu that allows users to organize results by breed, name, or age. The selected option is passed directly into the enhanced CRUD module, demonstrating separation between the user interface and the database layer. The data visualization was expanded by replacing the original breed distribution chart with a histogram that displays the age distribution of animals using Plotly. This visualization provides more meaningful insight into the available data and better demonstrates my ability to communicate information through graphical analysis. The interactive map was also improved. Selecting an animal now displays additional information including the animal's name, breed, color, and age inside the popup window instead of only displaying the name. This creates a more useful user experience while demonstrating how information retrieved from the database can be integrated into multiple user interface components. Overall, these enhancements transformed the original course project into a more complete database application that better reflects professional software development practices.
